## Build sequence

- Sep. 16–20: kickoff, access, setup, first contribution and initial scope. Keep this short opening period small.
- Sep. 21–27: backlog, one-page brief, architecture and capacity agreement.
- Sep. 28–Oct. 11: student shell, search/details, planning controls, save and export/import. Demo a usable vertical slice.
- Oct. 12–25: prerequisite/grade checks, map and reviewed data; decide the admin hosting path.
- Oct. 26–Nov. 29: prototype admin tools and requirement displays, drag/drop polish, usability and integration. Use the weekly checkpoints in Sprint 4.
- Nov. 30–Dec. 9: acceptance, packaging, documentation and fixes. Keep presentation preparation in parallel because its date is unknown.
- December, exact date TBD: closing report, six declarations and client handover.

## Critical dependencies

Client confirms curriculum interpretation → reviewed schema/fixtures → rule engine → map/requirements → acceptance. FCS hosting answer → backend deployment design → persistent admin editing → operational handover. Git access and local setup must precede individual implementation evidence.

If capacity drops, cut optional visual polish and stretch ideas first. Preserve usable student controls, visible uncertainty, export and required assessment evidence. Any reduction in the requested admin scope must be an explicit client decision recorded by PD; a static preview is not a completed hosted admin system.
